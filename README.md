# Room

Статический сайт для передачи камеры и микрофона между браузерами через PeerJS.

```sh
npm install
npm run peer
```

В другом терминале:

```sh
npm run dev
```

Node.js 22.20+. PeerServer работает отдельно на порту **9000**, сайт — на **3210**.
Нативных модулей и собственного серверного кода нет.

- `/` — отправитель с захардкоженным Peer ID `room`: чёрный экран, настройки справа сверху.
- `/client.html` — зритель, автоматически подключается к `room` и воспроизводит картинку и звук.

На ТВ-маке открой `http://localhost:3210/`, выбери камеру и микрофон в настройках.
Разрешения можно выдать кнопкой «Разрешить доступ к устройствам» или при первом подключении
зрителя. Главную страницу держим открытой в одном окне.

На другом Mac открой `http://IP-ТВ-МАКА:3210/client.html`. Для OBS это URL Browser Source
с включённым «Control audio via OBS». На странице зрителя нет кнопок и настроек,
видео запускается автоматически со звуком. При открытии в обычном браузере для сайта
нужно разрешить автозапуск со звуком, если браузер его блокирует.

Из возможностей камеры выбирается максимальное нативное разрешение, затем максимальная
доступная частота кадров для него. Ограничений 1080p и 30 fps нет. Масштабирование при захвате
отключено; при передаче задан масштаб 1:1 и приоритет сохранения разрешения и деталей.
Для видео устанавливается потолок 100 Мбит/с. Это разрешённый максимум, а не фиксированный
битрейт: WebRTC всё равно сжимает видео и управляет потоком с учётом сети и возможностей
кодека. При нехватке ресурсов частота кадров может снижаться. Несжатый/lossless режим не заявляется.
Камера захватывается один раз для всех зрителей. Для каждого зрителя создаётся отдельное
соединение. После ухода последнего зрителя камера и микрофон освобождаются.
Смена камеры или микрофона автоматически переподключает зрителей. Выбранные устройства
сохраняются в браузере. Аудиовыход на главной пока сохраняется для дальнейшего использования.
На стороне зрителя звуком управляет OBS или системный аудиовыход.

## Как устроено

`src/peer.ts` содержит постоянный ID и адрес PeerServer. По умолчанию адрес сервера совпадает
с адресом сайта, порт 9000, путь `/room`. Клиент открывает DataConnection к `room`, после чего
отправитель вызывает `peer.call(clientId, stream)`. Клиент отвечает без собственного потока.
SDP и ICE передаёт PeerJS. Медиа идёт напрямую между браузерами, внешний STUN/TURN не используется.
Проект рассчитан на одну локальную сеть. Постоянный Peer ID не является паролем.

Источник камеры должен открываться через localhost на машине с камерой или через HTTPS.
Страница зрителя не запрашивает локальную камеру и микрофон.

При необходимости адрес PeerServer можно задать перед запуском Vite или сборкой:

```sh
VITE_PEER_HOST=192.168.0.17 VITE_PEER_PORT=9000 npm run dev
```

При HTTPS-размещении сайта PeerServer также должен быть доступен по WSS.

## Сборка и проверка

```sh
npm run build
npm start
```

`dist/` — готовый статический сайт. Его можно разместить на любом статическом сервере;
обе страницы — `index.html` и `client.html` — обычные HTML-файлы. PeerServer запускается отдельно.

```sh
npm test
npm run format:check
```

Тесты используют синтетические камеру и микрофон в Chromium. Если Google Chrome не установлен
на macOS, сначала выполни `npx playwright install chromium`.

## Автозапуск на macOS

После клонирования репозитория на Mac с камерой:

```sh
npm ci
npm run build
npm run install:macos
```

Устанавливаются два LaunchAgent: `dev.dubrovin.room.site` и `dev.dubrovin.room.peer`.
Они работают независимо от SSH-сессии, запускаются при входе пользователя в macOS
и перезапускаются при сбое. Сайт раздаёт только собранную папку `dist/` через готовый
`sirv-cli`; PeerServer остаётся отдельным процессом. Логи — `~/Library/Logs/room/`.

Для обновления в клоне репозитория:

```sh
git pull --ff-only
npm ci
npm run build
npm run install:macos
```

Установщик запоминает абсолютный путь текущего Node. После обновления или удаления
этой версии Node запусти `npm run install:macos` снова.

Deploy key хранится только на машине развёртывания; для `git pull` достаточно
ключа с правами чтения одного репозитория.
