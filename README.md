# Room

Статический сайт для передачи камеры и микрофона между браузерами через PeerJS.

```sh
npm install
npm run peer
```

В другом терминале:

```sh
npm run dev
```

Node.js 22.20+. PeerServer работает отдельно на порту **9000**, сайт — на **3210**.
Нативных модулей и собственного серверного кода нет.

- `/` — отправитель с захардкоженным Peer ID `room`: чёрный экран, настройки справа сверху.
- `/client.html` — зритель, запрашивает камеру и микрофон у `room` и воспроизводит картинку и звук.
- `/share.html` — отправка выбранного экрана или окна на ТВ; камеру и микрофон комнаты не запрашивает.

На ТВ-маке открой `http://localhost:3210/`, выбери камеру и микрофон в настройках.
Разрешения можно выдать кнопкой «Разрешить доступ к устройствам» или при первом подключении
зрителя. Главную страницу держим открытой в одном окне.

На другом Mac открой `http://IP-ТВ-МАКА:3210/client.html`. Для OBS это URL Browser Source
с включённым «Control audio via OBS». На странице зрителя нет кнопок и настроек,
видео запускается автоматически со звуком. При открытии в обычном браузере для сайта
нужно разрешить автозапуск со звуком, если браузер его блокирует.

Из возможностей камеры выбирается максимальное нативное разрешение, затем максимальная
доступная частота кадров для него. Ограничений 1080p и 30 fps нет. Масштабирование при захвате
отключено; при передаче задан масштаб 1:1 и приоритет сохранения разрешения и деталей.
Для видео устанавливается потолок 100 Мбит/с. Это разрешённый максимум, а не фиксированный
битрейт: WebRTC всё равно сжимает видео и управляет потоком с учётом сети и возможностей
кодека. При нехватке ресурсов частота кадров может снижаться. Несжатый/lossless режим не заявляется.
Камера захватывается только по запросу зрителя, один раз для всех зрителей. Для каждого зрителя создаётся отдельное
соединение. После ухода последнего зрителя камера и микрофон освобождаются.
Смена камеры или микрофона автоматически переподключает зрителей. Выбранные устройства
сохраняются в браузере. Аудиовыход на ТВ выбирается нажатием «Применить» в настройках:
Safari требует пользовательского действия, поэтому при загрузке страницы выход не переключается.
На стороне зрителя звуком управляет OBS или системный аудиовыход.

## Как устроено

`src/peer.ts` содержит постоянный ID и адрес PeerServer. По умолчанию адрес сервера совпадает
с адресом сайта, порт 9000, путь `/room`. Клиент открывает DataConnection к `room` и отправляет `{ type: 'watch' }`, после чего
ТВ вызывает `peer.call(clientId, stream)`. Клиент отвечает без собственного потока.
Страница шаринга отправляет `{ type: 'share' }`, дожидается `{ type: 'ready' }` и звонит
ТВ со своим экраном. `{ type: 'stop-share' }` сразу убирает показ; новый отправитель
заменяет предыдущий. Входящие звонки без согласованного запроса шаринга отклоняются.
SDP и ICE передаёт PeerJS. Медиа идёт напрямую между браузерами, внешний STUN/TURN не используется.
Проект рассчитан на одну локальную сеть. Постоянный Peer ID не является паролем.

Источник камеры должен открываться через localhost на машине с камерой или через HTTPS.
Страница зрителя не запрашивает локальную камеру и микрофон.

При необходимости адрес PeerServer можно задать перед запуском Vite или сборкой:

```sh
VITE_PEER_HOST=192.168.0.17 VITE_PEER_PORT=9000 npm run dev
```

При HTTPS-размещении сайта PeerServer также должен быть доступен по WSS.

## Сборка и проверка

```sh
npm run build
npm start
```

`dist/` — готовый статический сайт. Его можно разместить на любом статическом сервере;
все страницы — `index.html`, `client.html`, `share.html` — обычные HTML-файлы. PeerServer запускается отдельно.

```sh
npm test
npm run format:check
```

Тесты используют синтетические камеру и микрофон в Chromium. Если Google Chrome не установлен
на macOS, сначала выполни `npx playwright install chromium`.

## Автозапуск на macOS

После клонирования репозитория на Mac с камерой:

```sh
npm ci
npm run build
npm run install:macos
```

Устанавливаются два LaunchAgent: `dev.dubrovin.room.site` и `dev.dubrovin.room.peer`.
Они работают независимо от SSH-сессии, запускаются при входе пользователя в macOS
и перезапускаются при сбое. Сайт раздаёт только собранную папку `dist/` через готовый
`sirv-cli`; PeerServer остаётся отдельным процессом. Логи — `~/Library/Logs/room/`.

Для обновления в клоне репозитория:

```sh
git pull --ff-only
npm ci
npm run build
npm run install:macos
```

Установщик запоминает абсолютный путь текущего Node. После обновления или удаления
этой версии Node запусти `npm run install:macos` снова.

Deploy key хранится только на машине развёртывания; для `git pull` достаточно
ключа с правами чтения одного репозитория.

## Показ экрана на ТВ

На Mac, с которого нужно показывать экран, в установленном проекте запусти:

```sh
npm run share
```

Откроется `http://localhost:3212/share.html`. Введи IP ТВ-мака (либо `IP:порт`,
по умолчанию PeerServer использует 9000), нажми «Подключиться», затем «Выбрать экран
или окно». Адрес сохраняется. Браузер покажет системный выбор доступных экранов,
окон или вкладок; набор вариантов зависит от браузера. При запросе разреши браузеру
доступ к локальной сети и запись экрана в macOS.

Картинка появится по центру ТВ с сохранением пропорций. Кнопка справа снизу на ТВ
переключает полноэкранный режим; выйти также можно через Escape. Кнопка «Остановить
показ» или завершение шаринга в браузере убирают картинку. Вместе с видео запрашивается
системный звук. На Mac используй современный Chrome и включи передачу звука в окне
выбора экрана/окна/вкладки. Если браузер не предоставит аудиодорожку, страница явно
покажет это в статусе. Камера и микрофон ТВ включаются независимо, при запросе страницы
`client.html`.

При первом показе со звуком на ТВ справа сверху появляется кнопка «Разрешить звук».
Нажатие включает звук для следующих трансляций в этой вкладке: видеоэлемент остаётся
тем же, смена потока больше не сбрасывает разрешение. Выбор сохраняется в браузере.
После перезагрузки страницы Room пробует включить звук автоматически; если браузер
блокирует автозапуск, видео продолжится без звука и кнопка появится снова.
Чтобы Safari разрешал звук и после перезагрузки, в настройках сайта localhost выбери
«Автовоспроизведение → Разрешить всё автовоспроизведение». На обычной странице
клиента OBS кнопок нет, звук по-прежнему воспроизводится автоматически.

`npm run share` запускает локальный сервер только для страницы. Сигналинг идёт через
указанный PeerServer, видеопоток — напрямую на ТВ. Localhost нужен для браузерного API
захвата экрана; отдельный сертификат не требуется. После обновления этой версии обнови
главную страницу ТВ и Browser Source в OBS: камера теперь запускается явным запросом.

## Статистика WebRTC

На `share.html` раскрой «Статистика WebRTC», на ТВ — открой настройки и тот же раздел.
Обе стороны опрашивают своё `RTCPeerConnection.getStats()` раз в секунду. На ТВ отдельно
видны приём экрана и отправка камеры каждому зрителю. Для диагностики приёма камеры
добавь `?stats=1` к URL Browser Source: `/client.html?stats=1`. Обычная клиентская страница
по-прежнему показывает только видео. Не открывай дополнительного зрителя ради статистики:
это создаст ещё один поток камеры; используй тот же Browser Source.

Панель показывает разрешение, FPS, кодек, битрейт, время кодирования/декодирования,
очередь отправки, буфер приёма, RTT и потери. Скорости и средние задержки считаются
по разнице двух последовательных отчётов. Первый отсчёт и неподдерживаемые поля
показываются как «—», а не ноль. Счётчики с пометкой «всего» накопительные; RTCP-потери
относятся к последнему отчёту удалённой стороны. «Скопировать» и «Скачать JSON» сохраняют
текущие показания всех медиасоединений на странице. При закрытии соединения его
статистика и таймер удаляются.

Время от первого принятого пакета до готового кадра уже включает ожидание в буфере
и декодирование: эти значения нельзя складывать. RTT — время туда-обратно, а не
полная задержка видео. Захват до кодировщика, вывод браузера и обработка изображения
телевизором здесь не измеряются. Сбор статистики не меняет настройки потоков.
